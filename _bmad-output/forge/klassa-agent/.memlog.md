- (decision) V1 Klassa Agent = chat assistant tunggal (guru ngobrol biasa), 3 skill: (1) admin: baca/analisis/report DB siswa, (2) ahli psikologi & pendidikan: diskusi tindakan siswa bermasalah / metode pembelajaran, (3) operasional: eksekusi fitur Klassa (misal bikin RPP)
- (assumption) Chat bersifat pribadi per-guru (bukan channel bersama); agent berjalan di dalam sesi guru terautentikasi
- (decision) Operasional: agent mengumpulkan input minimal via chat (maksimalkan data yang sudah ada di sistem), eksekusi HANYA setelah konfirmasi eksplisit guru; pola AI Studio draf->publish sebagai preseden reversible
- (decision) PII: OPSI A - data siswa apa adanya (nama, NIS, nilai, presensi, perilaku) boleh masuk prompt Gemini; pagar: (1) scope kuasa guru - agent hanya baca siswa rombel yang diampu (preseden isPengampuRombel/B2), (2) log percakapan & aksi agent di AuditLog bebas PIN/hash/secret (preseden redactMetadata)
- (note) Branch baru dari user: pakai Hermes (open-weight, Nous Research) sebagai model agent - vs default Gemini API. Dipelajari: self-host menyangkut PII, biaya GPU, kualitas function-calling; provider factory existing memungkinkan swappable
- (note) User ingin Hermes via MCP di sistem. Klarifikasi konsep: Hermes = model (endpoint OpenAI-compatible via vLLM/Nous API), MCP = lapisan tool. Opsi arsitektur: (1) embedded loop tanpa MCP, (2) Klassa MCP server terpisah + Hermes, (3) bertahap: tools MCP-compatible embedded lalu dibungkus jadi MCP server nyata
- (direction) User berubah arah: BIKIN AGENT SENDIRI (bukan Hermes+MCP). Analisis komponen custom agent loop, alternatif substrate (bare provider / Vercel AI SDK), risiko, effort. Keputusan sebelumnya (3 skill, konfirmasi, PII A+scope, provider-agnostic) tetap berlaku
- (lock) Arsitektur agen: Agen kustom Klassa dibangun di atas pipa AI SDK (Vercel AI SDK), provider-agnostic (Gemini v1 -> Hermes/vLLM v2 tanpa ubah tools)
- (lock) 3 Skill inti: (1) Admin: query data siswa/nilai/absen per pengampu, (2) Pedagogi/Psikologi: konsultasi non-klinis, (3) Operasional: aksi buat draf terkonfirmasi guru
- (lock) Human-in-the-loop: Agent meminta input minimal, merencanakan aksi, aksi eksekusi/tulis WAJIB konfirmasi eksplisit guru di UI chat
- (lock) Privasi & Batasan: PII siswa apa adanya dikirim ke LLM namun terkurung scope kelas guru (B2 isPengampuRombel), audit metadata teredaksi (redactMetadata)
- (lock) REVISI BLUEPRINT: (1) Dynamic Multi-Model (Gemini Flash default, High Reasoning, Hermes/Ollama on-premise), (2) Definisi tugas diperluas ke SEMUA fitur guru di Klassa dengan Matriks Konfirmasi Aksi (Read/Draft langsung, Sensitif/Publikasi WAJIB konfirmasi kartu chat), (3) Long-Term Memory guru (TeacherAgentMemory: gaya bicara, metode favorit, riwayat siswa), (4) Deterministic tools untuk hitungan database (anti halusinasi angka), (5) Tanpa kalkulasi biaya di blueprint
- (lock) Insight Engine: Klassa Pulse ditambahkan ke Admin Console (Story 6). Menampilkan visualisasi analitik makro: Top 10 Isu Kelas, Geographical Heatmap, Treemap Kurikulum Tersulit, Gauge Stres/Burnout Guru, dan Heatmap Jam Lembur Guru (Recharts, teranonimkan sesuai UU PDP)
- (lock) REVISI PENAJAMAN: (1) Universal Multi-Model: bebas pakai LLM apa pun (model komersial/open-weight via endpoint standar, daftar model sebelumnya hanya contoh), (2) Long-Term Memory: mampu merangkum inti pembahasan chat guru secara umum agar agen selalu nyambung, (3) Kalkulasi deterministik mencakup SEMUA hal di Klassa yang bisa dihitung (nilai, absen, ranking, durasi kuis, remedial, dsb.), (4) Pertanyaan pendidikan non-kelas dijawab 100%, pertanyaan non-pendidikan ditolak halus (polite deflection)
