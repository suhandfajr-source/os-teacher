Laporan Forge: Klassa Agent

Penajaman spesifikasi agen pintar guru dalam ekosistem Klassa OS

🛡️ Ringkasan Keputusan Terkunci (Locked)

1. Desain Chat Terpadu
Satu ruang dialog percakapan untuk semua interaksi guru. Agen secara otonom menentukan alat yang dipanggil berdasarkan maksud instruksi.
2. 3 Pilar Kemampuan
Admin (analisis database kelas), Pedagogis/Psikologi (konsultasi non-klinis), dan Operasional (bikin RPP, pesan ortu, draf materi).
3. Human-in-the-Loop Total
Agen hanya meminta input minimal. Setiap aksi yang menghasilkan karya atau data WAJIB dikonfirmasi melalui kartu interaktif sebelum disimpan ke draf.
4. Keamanan Scope B2
Data siswa dibaca apa adanya (nama & nilai) namun terisolasi mutlak hanya pada rombel yang diampu oleh guru tersebut (isPengampuRombel).
5. Agen Milik Sendiri (Native SDK)
Menggunakan Vercel AI SDK sebagai perpipaan ringan, menjamin logika alat, pagar, dan prompt 100% kustom tanpa terikat vendor.
6. Provider Agnostic (Gemini ➔ Hermes)
V1 menggunakan Gemini API untuk kecepatan dan efisiensi biaya. Kontrak alat bantu dirancang siap dialihkan ke Hermes mandiri saat siap.

❌ Alternatif yang Ditolak & Alasannya

  • Framework Penuh (LangChain / LangGraph): Ditolak karena abstraksi berlebihan yang memperumit kontrol kode di Next.js.
  • Menulis Loop Agent from Scratch: Ditolak karena menghabiskan 2–3 minggu hanya untuk urusan plumbing yang sudah diselesaikan secara matang oleh AI SDK standar.
  • Otonomi Eksekusi Otomatis (Tanpa Konfirmasi): Ditolak demi keamanan dan pencegahan halusinasi data kelas guru.
  • Pseudonimisasi Buta (Siswa A/B): Ditolak karena menyulitkan guru dalam memahami siswa mana yang sedang didiskusikan perilakunya.
  • Microservice MCP Server Terpisah di V1: Ditolak karena memicu beban pemeliharaan infrastruktur ekstra di fase rilis awal.
