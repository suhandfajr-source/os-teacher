## Findings

1. **Flag `dbAvailable` di-set tapi tidak pernah dikonsultasikan oleh test mana pun di `superadmin-seeder.int.test.ts`.** Pola referensi `import.db-concurrency.test.ts` menjaga setiap `it` yang butuh DB dengan `if (!dbAvailable) { expect(true).toBe(true); return; }`; file baru hanya memakai flag itu di `afterAll`. Akibat: DB down → seluruh 7 test DB merah keras, bukan soft-skip. Insiden yang bahkan terdokumentasi sendiri di Implementation Notes ("Neon sempat cold-start/unreachable → 1 run suite merah environmental (4 file)") adalah bukti langsung gap ini — dengan guard yang benar run itu akan hijau. Tambahkan guard per-test (atau `describe.skipIf` di level suite, meski cerita memilih pola flag manual — jadi ikuti pola manualnya).

2. **Fallback hard-exit default-nya `0` (success): `process.exit(process.exitCode ?? 0)`.** Timer 5 detik ini hanya menyala bila event loop masih hidup — yaitu persis skenario hang (mis. `pool.end()` macet, query tak kembali). Di skenario itu `main().then(...)` belum berjalan, `process.exitCode` masih `undefined`, dan script keluar dengan kode **0** — CI membaca kegagalan hang sebagai SUCCESS. Default fallback harus non-zero (`?? 1`).

3. **Identitas DB target baru dicetak SETELAH apply, melanggar Design Notes sendiri ("output selalu mencantumkan identitas DB target … sebelum apply — blast-radius wrong-DB").** CLI menghitung `target` lebih awal, tapi `host/dbname` hanya muncul di dalam `formatSeederReport` yang di-`console.log` setelah `runSuperadminSeed` resolve — untuk mode APPLY artinya setelah transaksi commit. Operator salah-DB tidak punya kesempatan melihat identitas sebelum tulisan terjadi. Cetak `target` segera setelah `describeDatabaseTarget()` (sebelum client init / pemanggilan core), atau tampilkan + konfirmasi interaktif untuk apply non-dry-run.

4. **`findFirst` insensitive + row duplikat case-variant mempromosikan row yang arbitrer.** Unique Postgres bersifat case-sensitive, jadi `A@x.y` dan `a@x.y` bisa legal berdampingan (row di luar better-auth — kelas row yang BH8 sendiri akui mungkin ada). Lookup `mode:"insensitive"` via `findFirst` diam-diam memilih salah satunya untuk dipromosikan — ini persis kelas bahaya perebutan identitas email (RT1) yang hendak dicegah. Pakai `findMany` dan abort sebagai *ambiguous* bila >1 match (lalu laporkan semua kandidatnya).

5. **Denylist `SENSITIVE_KEY_PATTERN` terlalu sempit untuk konsumen Stories 3–5 yang dijanjikan.** `apiKey`/`api_key`, `credential(s)`, `sessionId`, `privateKey`, `bearer`, `otp`, `jwt` semuanya lolos tanpa redaksi (contoh: `{ apiKey: "sk-..." }` tersimpan utuh). Karena `redactMetadata()` diposisikan sebagai invarian mekanis untuk SEMUA penulis AuditLog berikutnya, pola yang dipatok sekarang menjadi ceiling keamanan semua story mendatang — tambahkan minimal `key`, `credential`, `session` (dan pertimbangkan `otp`, `bearer`) plus test untuknya.

6. **Kontrak "Jalur seeder hanya untuk DB lokal" tidak ditegakkan sama sekali — konvensi komentar saja.** Tidak ada guard/peringatan ketika host hasil `describeDatabaseTarget` bukan localhost; Implementation Notes bahkan mengakui dry-run dijalankan menembus Neon dev bersama (`.env` menunjuk Neon). Minimal: warning mencolok di stdout saat host bukan localhost/127.0.0.1, atau catat keputusan sadar "tanpa guard" di Design Notes agar kontrak dan implementasi tidak berbeda diam-diam.

7. **`formatSeederReport` dan `describeDatabaseTarget` nol coverage — padahal laporan disebut "core deliverable" story.** Dua fungsi publik di `superadmin-seeder.ts` tidak punya test; `describeDatabaseTarget` punya edge nyata (URL tanpa path → `"(default)"`, IPv6, URL unparseable) dan menjadi fondasi sinyal blast-radius (finding 3), `formatSeederReport` membawa seluruh kontrak output operator (drift, unverified, plan flags, `sudah-ADMIN`). Unit test murni murah untuk keduanya.

8. **`describeDatabaseTarget` membuang port (`url.hostname`, bukan `url.host`).** `localhost:5432` vs `localhost:5433` tidak bisa dibedakan di output — justru di lingkungan lokal (target kontrak "DB lokal") multi-instance Postgres adalah kasus wrong-DB paling umum. Gunakan `url.host` (hostname+port).

9. **`.catch` terluar menelan error total: exit 1 tanpa output apa pun.** `parseArgs` (strict default) melempar untuk flag typo seperti `--dryrun` — `parseArgs` dipanggil di luar blok try/catch dalam `main()`, jadi rejection jatuh ke `main().catch(() => { process.exitCode = 1; })` yang membuang pesannya. Operator mendapat exit 1 senyap tanpa diagnostik. Bungkus `parseArgs` (atau log error di catch terluar).

10. **Opsi `pool?: Pool` di `runSuperadminSeed` mati — diterima, didokumentasikan ("Optional pool so tests…"), tak pernah dipakai.** Ini juga satu-satunya alasan modul meng-import tipe `Pool` dari `pg`. Hapus opsi itu (dan import-nya), atau benar-benar wiring — API publik yang mengklaim fungsi tanpa efek adalah jebakan bagi pemanggil berikutnya.

11. **Daftar Verification story tidak diamendemen meski eksekusinya menyimpang.** Verification masih mewajibkan `npm run seed:superadmin` (env valid, 2×) — sementara Implementation Notes mengakui apply CLI nyata sengaja tidak dijalankan (Neon bersama) dan disubstitusi test integrasi. Deviasi itu masuk akal, tetapi checklist story sendiri kini memuat item yang diketahui tidak dijalankan tanpa penanda — tandai item tersebut (mis. "diverifikasi via test integrasi, CLI apply ditunda ke operator — lihat Implementation Notes") agar door-criteria review tidak membaca checklist sebagai kebohongan.

12. **Fail-fast allowlist diduplikasi di CLI dan di core — dua sumber kebenaran.** CLI mengecek `emails.length === 0 && invalid.length === 0` + invalid list dengan pesan bespoke; core melempar `SeedConfigError` untuk kondisi yang sama. Keduanya harus berkembang serempak (mis. bila nanti ada kondisi config baru, mis. batas jumlah entri). Biarkan core yang melempar, CLI cukup render `SeedConfigError` — pesan CLI saat ini bahkan lebih kabur daripada punya core.

13. **Pesan error CLI menyesatkan: "periksa .env (script memuat .env otomatis)".** Script TIDAK memuat `.env` — loading dilakukan flag `--env-file-if-exists=.env` di npm script (premis C1 cerita sendiri: "tsx tidak memuat .env otomatis"). Jalankan via fallback terdokumentasi `node --env-file-if-exists=.env --import tsx …` tanpa flag env, atau `tsx scripts/seed-superadmin.ts` langsung, dan pesan ini menuntun operator ke diagnosis salah.

14. **Churn lockfile melampaui penambahan tsx.** Hilangnya massal field `libc` dari banyak paket platform (sharp/libsql/rollup), flip `devOptional→dev` (`@types/react-dom`, `fsevents`), dan duplikasi `fsevents@2.3.3` (root + nested di bawah `tsx` versi identik) konsisten dengan regen oleh versi npm berbeda, bukan instalasi minimal `tsx`. Risiko: konflik lockfile bagi kontributor lain + install bloat; verifikasi regen dengan npm versi pinned/CI, dan pertimbangkan kenapa fsevents tidak ter-hoist.

15. **Sinyal akun `hasTeacherProfile` (F3) tidak pernah diuji true.** Semua user test dibuat tanpa TeacherProfile — field `hasTeacherProfile` di plan dan cabang `"TeacherProfile=ada"` di `formatSeederReport` tidak pernah dieksekusi dengan nilai true di seluruh suite. Satu test yang membuat row `TeacherProfile` untuk user allowlist akan menutup jalur sinyal RT1 yang dijanjikan spec.
