# Review 1c — Verification Gap Findings

Metode: screen perilaku → telusuri konsumen → baca test → konfirmasi. Semua klaim "tidak ada test" di bawah didukung pencarian simpan/referensi-import di seluruh repo (`rg` di luar `node_modules` dan `_bmad-output`), dan semua klaim "test X meng-cover Y" didukung pembacaan test aktual di repo. Bagian non-behavioral (`.env.example`, file story, `.env` docs) di-skip. Bagian yang terbukti ter-cover penuh dan bukan temuan: kontrak parser (matriks I/O unit test), kontrak `redactMetadata` (unit test lengkap), gerbang pre-write all-or-nothing, gate unverified + penanda audit bypass, insensitive lookup, idempotensi, drift-tanpa-demosi, dry-run (semua di `superadmin-seeder.int.test.ts`, ter-run di jalur normal — `vitest.config.ts` include `src/**/*.test.ts` terkonfirmasi memuat file tersebut). Tidak ada penulis AuditLog lain di repo (satu-satunya: `src/lib/superadmin-seeder.ts:214`) sehingga tidak ada missing-adoption `redactMetadata` saat ini; juga tidak ada pembaca AuditLog sehingga tidak ada contract-drift konsumen.

### Guard `dbAvailable` di-set tetapi tidak pernah dikonsultasikan test — pola skip mati sebelum dipakai

- **Changed surface:** test integrasi seeder baru `src/lib/__tests__/superadmin-seeder.int.test.ts:14,48-54` mengklaim mengikuti pola guard `dbAvailable` (komentar header :8-10 "mirrors import.db-concurrency.test.ts (NOT skipIf)").
- **Impacted consumer or site:** keenam test DB-dependent dalam file itu (`:75-160`) — jalur verifikasi normal `npm test` untuk seluruh perilaku inti seeder (BH12/BH7/BH8).
- **Existing test evidence:** pola referensi yang dikutip benar-benar memakai flag-nya: `src/modules/imports/__tests__/import.db-concurrency.test.ts:111-114` dan `:183-186` mengawali setiap test DB dengan `if (!dbAvailable) { expect(true).toBe(true); return; }`. File baru hanya membaca `dbAvailable` di `afterAll` (`:57-58`) untuk cleanup — grep `dbAvailable` di file itu menghasilkan persis baris 14/51/53/58, tidak ada satu pun di badan test.
- **Missing verification:** assertion-skip `if (!dbAvailable) return;` (atau padanan) di setiap test yang menyentuh DB — tanpa itu, flag-nya murni hiasan.
- **Demonstration:** matikan DB / hapus `DATABASE_URL` yang diwarisi dotenv → `beforeAll` men-set `dbAvailable=false`, tetapi test "aborts all-or-nothing…" (`:87`) tetap memanggil `createTestUser` → `prisma.user.create` reject → suite **merah**, bukan hijau-skip. Insiden ini sudah terjadi nyata: story sendiri mencatat "Neon sempat cold-start/unreachable → 1 run suite merah environmental (4 file)" (Implementation Notes stage 3). Regresi kode dan gangguan lingkungan jadi tak terbedakan — daya pisah verifikasi hilang, dan failure-set comparison (presedepun OQ1=A 1b) berubah dari "flake dikenal satu file" menjadi "merah tak terduga 4 file".
- **Consequence:** setiap gangguan lingkungan (Neon cold-start, .env tak termuat, VPN putus) dikreditkan sebagai kegagalan regresi story 1c; kebalikannya, kebiasaan "merah environmental, abaikan" membuka pintu regresi inti seeder lolos karena suite memang sering merah.
- **Disposition:** `patch` — salin guard literal dari test referensi (`if (!dbAvailable) { expect(true).toBe(true); return; }`) ke kepala keenam test DB; konsisten dengan gaya repo yang sudah dikutip komentar file itu sendiri.

### CLI `scripts/seed-superadmin.ts` — termasuk `formatSeederReport` dan `describeDatabaseTarget` — nol verifikasi otomatis, padahal acceptance criteria story adalah observabel CLI

- **Changed surface:** entry point operator `scripts/seed-superadmin.ts:21-102` (exit code, pesan fail-fast `:34-37,:44,:50`, passthrough flag `--dry-run`/`--allow-unverified` `:21-26`, pencetakan laporan `:68`, laporan abort `:77-79`) plus dua fungsi ekspor murni `formatSeederReport`/`describeDatabaseTarget` (`src/lib/superadmin-seeder.ts:229-279`) yang hanya CLI yang memanggil.
- **Impacted consumer or site:** operator/CI menjalankan `npm run seed:superadmin` (script di `package.json:12`) — permukaan acceptance criteria story ("exit non-zero dan nol row berubah", dry-run + identitas DB, idempotent 2×) secara harfiah adalah output CLI.
- **Existing test evidence:** pencarian seluruh repo atas `seed-superadmin`, `seed:superadmin`, `formatSeederReport`, `describeDatabaseTarget`, `runSuperadminSeed`, `SeedAbortError`, `SeedConfigError` hanya menghasilkan: definisi di modul, pemanggilan CLI, int test core (`runSuperadminSeed` saja — tidak mengimpor dua formatter), dan satu baris docs (`docs/products/DEV_STAGE_11_STUDENT_PORTAL_AUTH.md:207`). Tidak ada file test yang mengeksekusi CLI atau dua formatter tersebut. Verifikasi yang ada atas CLI adalah run manual operator yang didokumentasikan story (Implementation Notes stage 3 dan "verifikasi akhir") — human-only check, tidak dihitung.
- **Missing verification:** assertion atas exit code dan stdout CLI untuk tiga skenario acceptance (no-env → 1, invalid-entry → 1 + daftar, dry-run env-valid → 0 + identitas DB + nol row); dan unit assertion atas `formatSeederReport` (blok drift, warning bypass, baris DB target) serta `describeDatabaseTarget` (URL valid, path default, unparseable).
- **Demonstration:** balik `return 1` → `return 0` pada cabang allowlist-kosong (`scripts/seed-superadmin.ts:37`), atau buat `describeDatabaseTarget` selalu mengembalikan `"(unparseable)"`, atau ganti passthrough `values["dry-run"]` → `false` konstan — `npm test` tetap 551/551 hijau karena tidak ada satu pun test yang mengobservasi keluaran CLI/formatter. Acceptance criteria story sendiri yang jadi tak terpin.
- **Consequence:** satu-satunya jalur pemakaian nyata hasil story ini (operator mempromosikan superadmin) bisa rusak dalam diam — exit code terbalik di CI pipeline future, laporan identitas-DB salah (blast-radius wrong-DB yang justru ingin dicegah), flag dry-run mati — tanpa satu test merah.
- **Disposition:** `patch` — dua langkah pas dengan infra repo: (1) unit test vitest untuk `formatSeederReport`/`describeDatabaseTarget` (fungsi murni, murah, mengikuti gaya `superadmin-allowlist.test.ts`); (2) satu test spawn tipis `execFile("tsx", ["--env-file-if-exists=.env", "scripts/seed-superadmin.ts"], { env terkontrol })` memeriksa exit code + stdout untuk skenario no-env dan invalid-entry (dry-run memerlukan env valid — boleh defer bila DI DB test tak tersedia).

### Atomicitas apply (UPDATE + insert AuditLog dalam SATU transaksi, kontrak F4) tidak diobservasi test mana pun

- **Changed surface:** komposisi transaksi di `src/lib/superadmin-seeder.ts:132` — loop apply `:204-227` menjalankan `tx.user.update` (`:210-213`) dan `tx.auditLog.create` (`:214-226`) dalam satu interactive tx; kontrak eksplisit header modul `:12-17` ("plan and apply cannot drift apart (TOCTOU), and a promotion without its audit entry is impossible").
- **Impacted consumer or site:** row `User.platformRole` dan `AuditLog` di DB target — konsumen audit forensik (jejak promosi SYSTEM) yang dirancang story.
- **Existing test evidence:** dibaca seluruh `src/lib/__tests__/superadmin-seeder.int.test.ts`: test all-or-nothing (`:87-101`) hanya membuktikan gerbang PRE-write (unknown email → abort sebelum tulis); test "marks the audit" (`:104-125`) dan idempotency (`:133-150`) membuktikan audit ADA setelah apply sukses — keduanya tetap lulus walau `auditLog.create` dipindah keluar transaksi. Tidak ada test yang menggagalkan apply di tengah jalan.
- **Missing verification:** assertion bahwa kegagalan DI FASE APPLY (setelah minimal satu `user.update` berhasil) memutar balik seluruh perubahan — user pertama kembali `platformRole="USER"` dan nol row audit tersisa.
- **Demonstration:** refactor `auditLog.create` keluar dari callback `$transaction` (atau kedua operasi entri kedua) → seluruh suite tetap hijau (jumlah audit pasca-sukses tidak berubah, idempotensi tetap 0-entri-baru). Kontrak "promosi tanpa entri audit mustahil" regresi senyap: crash/timeout antara update dan audit kini meninggalkan ADMIN tanpa jejak — persis skenario audit-log dirancang untuk mencegah.
- **Consequence:** jaminan forensik inti story (setiap promosi selalu berpasangan audit) hanya berupa klaim kode, bukan perilaku terverifikasi; perubahan masa depan pada struktur loop/tx bisa membongkarnya tanpa sinyal test.
- **Disposition:** `patch` — satu test integrasi fault-injection: bungkus prisma (parameter injeksi `prisma` sudah disediakan justru karena core diekstrak agar testable) dengan Proxy yang meneruskan `$transaction` tetapi membungkus `tx` sehingga `auditLog.create` melempar untuk `targetId` tertentu; allowlist dua user (satu normal, satu sandungnya), expect throw DAN user pertama tetap `USER` + `auditCountFor === 0`. Real-DB, konsisten gaya int test existing.

## Other findings

- `findUserInsensitive` (`src/lib/superadmin-seeder.ts:91-108`) memakai `findFirst` tanpa `orderBy` atas lookup `mode: "insensitive"`; `@@unique([email])` (`prisma/schema.prisma:170`) bersifat case-sensitive di Postgres sehingga row varian-case dapat hidup berdampingan — skenario yang justru dibuktikan mungkin oleh test int sendiri yang membuat row mixed-case di luar better-auth. Dua row varian-case → seeder mempromosikan salah satunya secara arbitrer, tanpa deteksi ambiguitas.
- Fallback hard-exit CLI `scripts/seed-superadmin.ts:102` (`setTimeout(() => process.exit(process.exitCode ?? 0), 5_000).unref()`) lebih pendek dari `TRANSACTION_TIMEOUT_MS = 15_000` (`src/lib/superadmin-seeder.ts:25`): apply sah yang lambat (Neon cold-start sudah terdokumentasi di story) terbunuh di tengah jalan, dan karena `main()` belum resolve, `process.exitCode` masih undefined → keluar kode **0** — keberhasilan palsu di CI.
- `vitest.config.ts:1` mengimpor `import "dotenv/config"` tetapi `dotenv` tidak dideklarasikan di `package.json` (terpasang `node_modules/dotenv` 17.4.2 via transitive). Mekanisme warisan `DATABASE_URL` yang diandalkan seluruh test integrasi (story elicitation F1) bertumpu pada phantom dependency; deklarasikan sebagai devDependency.
- Laporan abort dicetak hanya ke stderr (`scripts/seed-superadmin.ts:77-79`) — `npm run seed:superadmin > seed.log` kehilangan laporan yang oleh story disebut deliverable inti (rasional F2 justru melindungi stdout ter-pipe).
- Flag `--env-file-if-exists` mensyaratkan Node ≥ 20.12 (tsx sendiri hanya ≥ 18) dan `package.json` tanpa field `engines`; di Node 18–20.11 script mati "bad option" — tidak ada jalur verifikasi otomatis yang akan menangkapnya (beririsan dengan gap CLI di atas).
