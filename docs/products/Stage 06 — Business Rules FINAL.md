# Stage 06 — Business Rules
## AI Teacher Assistant — Final Revised

## 1. Tujuan Stage

Menentukan aturan main sistem: kapan fitur dapat digunakan, data yang wajib/opsional, apa yang terjadi setelah aktivitas tertentu, konsistensi data, dan batas antara keputusan guru dengan bantuan AI.

Prinsip utama:

> **Sistem harus fleksibel untuk guru, tetapi tetap ketat dalam menjaga kualitas dan konsistensi data.**

## 2. Minimal Setup

Guru boleh mulai dengan:

```text
Guru
+
Mapel
+
Kelas
+
Siswa
```

Tidak wajib memiliki:

- Kurikulum
- CP
- TP
- ATP
- Prota
- Prosem
- RPP

Academic Context meningkatkan kualitas fitur, tetapi tidak mengunci fitur dasar.

## 3. Start Anytime

Guru dapat mulai kapan saja dalam semester.

Pilihan:

- Start Now
- Quick Backfill
- Full Import

Historical data dapat bersifat:

- Complete
- Partial
- Summary

Sistem harus dapat menunjukkan coverage jika data belum lengkap.

## 4. Input Once, Use Everywhere

Jika data sudah diketahui sistem, guru tidak diminta menginput ulang tanpa alasan.

Contoh: data tanggal, kelas, mapel, guru, dan materi dari Teaching Session otomatis digunakan untuk jurnal.

## 5. Ask Only When Needed

Sistem meminta data hanya saat diperlukan.

Contoh minimum generate soal:

```text
Mapel
Kelas
Materi
Jumlah Soal
Jenis Soal
```

CP / TP / ATP optional.

## 6. Teaching Session

Setiap aktivitas pembelajaran harian sebaiknya dikaitkan dengan Teaching Session.

Satu session dapat memiliki:

- absensi,
- materi,
- aktivitas,
- tugas,
- catatan,
- jurnal.

TP bersifat optional.

## 7. Absensi

Status utama:

- Hadir
- Sakit
- Izin
- Alpha
- Terlambat

Rule:

- satu siswa satu status utama per session,
- absensi dapat diperbaiki guru,
- perubahan penting dapat memiliki histori,
- rekap dihitung otomatis,
- guru tidak menghitung persentase manual.

## 8. Jurnal Mengajar

Jurnal dibentuk dari:

```text
Teaching Session
+
Materi
+
Aktivitas
+
Catatan
```

Flow:

```text
Generate Draft
↓
Review
↓
Edit
↓
Finalize
```

Jurnal bukan form terpisah yang mengharuskan input ulang data yang sudah tersedia.

## 9. Assignment

Status:

- Belum Mengumpulkan
- Sudah Mengumpulkan
- Terlambat

Nilai bersifat opsional.

Tidak semua tugas wajib dinilai.

## 10. AI Generation

Semua generator AI memiliki dua mode:

```text
AUTOMATIC
MANUAL
```

Flow:

```text
GENERATE
↓
REVIEW
↓
EDIT
↓
SAVE
```

AI output penting tidak langsung dianggap final tanpa review guru.

## 11. AI Tidak Memaksakan Academic Context

Tanpa CP/TP, guru tetap dapat membuat:

- soal,
- PPT,
- LKPD,
- worksheet,
- materi,
- rencana pembelajaran,
- aktivitas.

Optional context tidak boleh menjadi blocking.

## 12. AI Output Traceability

Setiap hasil AI sebaiknya menyimpan:

- Generated By
- Generated At
- Mode
- Context Source
- Prompt
- Version

## 13. RPP sebagai Referensi

RPP bersifat optional.

Dapat digunakan sebagai context untuk:

- PPT,
- LKPD,
- worksheet,
- soal,
- quiz,
- aktivitas pembelajaran.

## 14. Assessment — V1 Final

Assessment dapat dibuat berdasarkan:

```text
Materi
```

atau:

```text
Materi + TP
```

atau:

```text
Kisi-kisi
```

Guru:

- melaksanakan assessment,
- mengoreksi jawaban siswa,
- menentukan nilai.

Sistem:

- menyimpan assessment,
- menyimpan soal/kunci,
- menerima nilai,
- mengolah nilai,
- menganalisis hasil.

## 15. Soal

Soal dapat dibuat:

- manual,
- AI,
- bank soal.

Metadata seperti TP, level kognitif, dan kesulitan dapat bersifat optional sesuai kebutuhan.

## 16. Koreksi & Nilai — V1

**Koreksi dilakukan secara manual oleh guru.**

AI pada V1 tidak:

- menilai essay,
- membaca lembar jawaban,
- menentukan skor,
- mengoreksi otomatis.

Guru memasukkan hasil koreksi ke sistem.

Sistem harus mempermudah input nilai.

## 17. Rule Nilai

Nilai dapat menyimpan:

```text
Raw / Input Score
Manual Adjustment jika ada
Final Score
```

Perubahan signifikan dapat memiliki histori.

## 18. Remedial

Sistem dapat merekomendasikan kandidat remedial berdasarkan nilai.

Guru tetap menentukan peserta remedial.

Simpan:

```text
Nilai Awal
+
Nilai Remedial
+
Nilai Final
```

Nilai awal tidak hilang.

## 19. Ketuntasan

Standar ketuntasan dapat berasal dari:

- KKTP,
- passing grade,
- custom guru.

Jika tidak tersedia, sistem tetap dapat melakukan analisis distribusi dan tren nilai.

## 20. Student Monitoring

Student Monitoring adalah hasil agregasi.

```text
Attendance
+
Assignment
+
Assessment
+
Score
+
Remedial
+
Teacher Notes
↓
STUDENT MONITORING
```

Guru tidak diminta membuat data monitoring ulang.

## 21. Insight

Sistem membedakan:

### Data Fact

> Ahmad belum mengumpulkan 3 tugas.

### System Interpretation

> Ahmad mungkin membutuhkan perhatian terkait konsistensi pengerjaan tugas.

Fakta dan interpretasi tidak boleh dicampur tanpa penjelasan.

## 22. Confidence & Data Coverage

Jika analisis menggunakan data tidak lengkap, sistem harus memberi indikator coverage/confidence.

Contoh:

```text
Data Coverage: 62%
Confidence: Medium
```

## 23. Teacher Notes

Visibility:

```text
PRIVATE
PARENT_VISIBLE
```

Default:

```text
PRIVATE
```

Catatan internal guru tidak otomatis muncul ke orang tua.

## 24. Parent Portal

Orang tua hanya dapat:

- melihat anak sendiri,
- melihat data yang diizinkan,
- melihat informasi perkembangan.

Orang tua tidak dapat:

- mengubah data,
- melihat siswa lain,
- melihat catatan private,
- mengakses workspace guru.

## 25. Parent Communication

AI dapat membantu menyusun draft pesan.

```text
Data Siswa
↓
AI Draft Message
↓
Guru Review
↓
Send / Copy
```

AI tidak otomatis mengirim komunikasi penting.

## 26. Reporting

```text
CORE DATA
↓
REPORT ENGINE
↓
DRAFT
↓
REVIEW
↓
FINAL
```

Report berasal dari data sistem, bukan input ulang.

## 27. Finalized Report

Jika report telah finalized:

- sistem dapat menyimpan snapshot,
- perubahan data berikutnya tidak mengubah snapshot lama,
- guru dapat menghasilkan versi baru.

## 28. Template Sekolah

Template administrasi tidak boleh mempengaruhi struktur core data.

```text
CORE DATA
↓
TEMPLATE
↓
DOCUMENT
```

Perubahan template tidak merusak data yang tersimpan.

## 29. Prota & Prosem

Prota dan Prosem dapat:

- dibuat manual,
- digenerate AI,
- di-import,
- dibentuk dari data planning/actual teaching.

Keduanya tidak menjadi dependency wajib Teaching atau Assessment.

## 30. Planned vs Actual

Planning dan actual teaching disimpan terpisah.

Contoh:

```text
PLANNED:
Sistem Pernapasan — Minggu 8
```

```text
ACTUAL:
Sistem Pernapasan — Minggu 10
```

Keduanya tetap disimpan sehingga dapat dibandingkan.

## 31. Import Data

Import melalui:

```text
UPLOAD
↓
PREVIEW
↓
MAPPING
↓
VALIDATION
↓
CONFIRM
↓
IMPORT
```

Duplicate data harus dideteksi sebisa mungkin.

## 32. Historical Data

Historical data boleh:

- Complete
- Partial
- Summary

Guru tidak wajib merekonstruksi seluruh aktivitas semester.

## 33. Delete vs Archive

Data penting seperti:

- assessment,
- nilai,
- remedial,
- Teaching Session

sebaiknya menggunakan:

```text
ARCHIVE / SOFT DELETE
```

daripada langsung dihapus permanen.

## 34. Edit History

Data penting seperti:

- nilai,
- absensi,
- remedial,
- finalized report

sebaiknya menyimpan histori perubahan yang relevan.

## 35. AI Recommendation

AI boleh:

- generate,
- merangkum,
- merekomendasikan,
- menjelaskan,
- membuat draft.

AI **tidak menentukan nilai siswa pada V1**.

Prinsip:

> **AI assists, teacher decides.**

## 36. Dashboard & Statistik

Dashboard tidak memiliki input statistik sendiri.

Semua statistik berasal dari core data aktual.

## 37. Progressive Enhancement

### Level 1

```text
Minimal Data
↓
Daily Features
```

### Level 2

```text
Activity History
↓
Monitoring + Trend
```

### Level 3

```text
Academic Context
↓
Curriculum Analysis + Full Reporting
```

Guru tidak wajib naik ke Level 3.

## 38. Core Business Rules Final

1. Minimal data cukup untuk mulai bekerja.
2. Academic Context optional.
3. Jangan minta data yang sudah diketahui sistem.
4. Guru dapat mulai kapan saja dalam semester.
5. AI memiliki Automatic dan Manual Mode.
6. Guru memegang keputusan akademik.
7. Aktivitas guru otomatis menjadi sumber monitoring.
8. Report berasal dari data, bukan input ulang.
9. Planned dan Actual dibedakan.
10. Semakin lengkap data, semakin dalam analisis.
11. **Guru mengoreksi manual pada V1.**
12. **Sistem mengolah nilai setelah guru menginput hasil koreksi.**

## 39. Business Rule Philosophy

> **Input Once, Use Everywhere**

> **Ask Only When Needed**

> **Start Anytime, Grow the Context**

> **More Context = Better Experience**

> **AI Assists, Teacher Decides**

> **Activity Generates Data**

> **Report by Product**

> **Automate Administration First, Automate Judgment Later**

**STAGE 06 — BUSINESS RULES: FINAL REVISED**
