🔐 Kerangka: Jalur Terpisah Superadmin (Single-Admin Lane)

Menutup 4 celah: guru tak bisa jadi superadmin, superadmin tak lahir dari register, email reserved, lane terpisah penuh. · 2026-09-24

1. Alur Sekarang (dan kenapa harus ganti)

Register guru /register (publik) → sign-up Better Auth → User biasa (role user) → login → /dashboard → wizard onboarding → TeacherProfile + Sekolah + Kelas → persetujuan superadmin.
Superadmin .env: SUPERADMIN_EMAILS → daftar dulu via pintu publik yang SAMA dengan guru → set emailVerified manual → npm run seed:superadmin → promote platformRole ADMIN.
#CelahDampak
C1Seeder tidak peduli akun itu guru — akun ber-TeacherProfile bisa dipromosikanGuru bisa jadi superadmin dilarang
C2Akun superadmin lahir dari pintu publik (/register)Tidak ada pemisahan identitas sejak lahir
C3Email allowlist tidak di-reserve di /registerBisa disquat orang lain
C4Superadmin bisa ikut onboarding guru (hibrida)Batas lane kabur

2. Invariant Baru

  • I1 — Lahir dari seeder saja. Superadmin hanya diciptakan lewat SUPERADMIN_EMAILS + seeder. Tidak pernah dari /register.
  • I2 — Guru tidak pernah naik. Akun PUBLIC_REGISTER tidak bisa dipromosikan — seeder abort, nol baris berubah (termasuk akun guru maupun akun publik tanpa profil).
  • I3 — Email reserved. Email di SUPERADMIN_EMAILS ditolak di /register & API signup (pesan jelas, tidak membocorkan daftar).
  • I4 — Lane terpisah penuh. Superadmin: login → /admin, tidak bisa masuk jalur guru. Guru: tidak bisa /admin (sudah ada, dipertahankan).
  • I5 — Satu superadmin: kamu. Allowlist = tepat 1 email (suhandfajr5@gmail.com). Kode mendukung multi untuk DR, tidak dipakai.

3. Desain Teknis

3.1 Skema (migrasi kecil)

model User {
  registrationOrigin RegistrationOrigin?  // PUBLIC_REGISTER | PLATFORM_SEED
}
enum RegistrationOrigin { PUBLIC_REGISTER PLATFORM_SEED }

User lama (semua) → PUBLIC_REGISTER via migrasi. Seeder menulis PLATFORM_SEED untuk akun yang ia ciptakan/adopsi.

3.2 Seeder (superadmin-seeder.ts + CLI)

  1. Create-when-missing: email allowlist tak ditemukan → seeder membuat akunnya — password dari SUPERADMIN_INITIAL_PASSWORD atau prompt interaktif (tidak pernah di-log), hash via helper Better Auth; emailVerified: true, PLATFORM_SEED, promote — satu transaksi + audit.
  2. Promote-existing hanya untuk PLATFORM_SEED: akun PUBLIC_REGISTER → SeedAbortError (nol row). Menutup C1+C2.
  3. Drift report ADMIN-di-luar-allowlist tetap (BH7, tidak auto-demosi).

3.3 Register / API signup

Validasi di server action register dan hook user.create.before Better Auth: email ∈ allowlist → tolak. Menutup C3.

3.4 Routing & guard pasca-login

  • Redirect pasca-login: platformRole = ADMIN → /admin.
  • Guard jalur guru (onboarding, /kelas/**): tolak ADMIN → lempar /admin. Menutup C4.
  • /admin tetap requireSuperAdmin (tanpa perubahan).

3.5 Migrasi akunmu (sekali jalan)

Akun suhandfajr5@gmail.com hari ini = PUBLIC_REGISTER. Solusi: flag seeder --adopt — set origin = PLATFORM_SEED hanya bila akun belum punya TeacherProfile → transaksi + audit. Setelah adopsi, I2 mengunci permanen.

5. Out of Scope

Multi-superadmin · undang admin · UI kelola allowlist · 2FA.

6. Urutan Implementasi

  1. Migrasi skema registrationOrigin (default user lama → PUBLIC_REGISTER)
  2. Seeder --adopt → jalankan untuk akunmu
  3. Seeder create-when-missing + gate origin (I1+I2)
  4. Tolak email reserved di register/signup (I3)
  5. Redirect & guard lane (I4)
  6. Tests + update docs/CHECKLIST-FITUR.md (bagian Superadmin)
